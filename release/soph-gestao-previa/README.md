# Liberação controlada do Soph Gestão 2.0

1. Após aprovação, confirmar o projeto Auth do EmpreendaJá correspondente ao frontend e o UUID da conta administradora existente. Configurar `SOPH_GESTAO_PREVIEW_ADMIN_ID` com esse UUID e `SOPH_GESTAO_PREVIEW_ORIGIN` com a origem HTTPS exata do frontend, sem barra final. Definir ambos no ambiente da Edge Function.
2. Publicar somente a função `soph-gestao-preview` nesse projeto, por exemplo com `supabase functions deploy soph-gestao-preview --project-ref <ref-do-auth-do-empreendaja>`. A função usa a URL e a chave anônima do próprio projeto e verifica o token por `auth.getUser`. Preservar as demais funções e configurações. Nenhum SQL do PR #24 participa da liberação.
3. Publicar o frontend pelo fluxo aprovado, com a reescrita SPA existente. Aplicar primeiro em ambiente isolado que use o Auth correspondente. O cliente atual fixa o projeto de Auth em `src/integrations/supabase/client.ts`. Uma homologação com Auth próprio exige apontar o build de homologação para esse projeto e usar contas de teste.
4. Conferir a entrada pela Gestão e a abertura direta de `/gestao/soph-gestao` e das subrotas. A administradora deve entrar com a sessão atual. Uma assinante comum deve receber 403 na função, continuar com seus acessos habituais e não ver o link de prévia. Sem sessão, a rota deve encaminhar ao login existente. Conferir também os formulários em memória e a perda das alterações ao recarregar.
5. Para suspender a liberação, remover `SOPH_GESTAO_PREVIEW_ADMIN_ID` da função ou reverter o frontend. Novas verificações serão negadas. Abas já autorizadas contêm apenas a demonstração e podem permanecer abertas até nova verificação da sessão ou da rota.
